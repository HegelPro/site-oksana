# Сайт онлайн-курсов Оксаны

Монорепозиторий на pnpm: `apps/web` — сайт на Next.js с серверным рендерингом, `packages/catalog` — типизированный каталог курсов. Сейчас страницы содержат демонстрационные тексты и оформление.

Дизайн использует предоставленные логотип и фотографии из `apps/web/public/images`. Шрифты Manrope и Cormorant Garamond с кириллицей поставляются локально через Fontsource: запросы к Google Fonts при открытии сайта и сборке не нужны.

Опубликован курс «Йога и аюрведа для внутреннего спокойствия»: `/courses/yoga-ayurveda-inner-calm`. Программа, подарки, афиша и условия участия хранятся в каталоге. Демонстрационные записи помечены `draft` и не выводятся на главной и в каталоге. Срок ранней цены установлен до 31 октября 2026 года включительно; после него текущая цена — 5 999 ₽, предложение 2 999 ₽ отображается как завершённое. Для следующего набора обновите даты и `earlyOffer.until`, не продлевая скидку автоматически.

Вторая отдельная программа: `/courses/yoga-ayurveda-14-days`, 11–25 ноября 2026 года. Полная последовательность 14 дней и результаты хранятся в `curriculum`; дни раскрываются нативными элементами `details`. Цена не задана — условия уточняются при записи. Заявки различаются по `courseSlug`, даже при одинаковых названиях курсов.

## Локальная разработка

### Стили и компоненты

Весь интерфейс использует **Tailwind CSS 4** через `@tailwindcss/postcss`. Единственная глобальная таблица — `apps/web/src/app/globals.css`: импорт Tailwind, токены `@theme` и базовые правила типографики, фокуса и уменьшения движения. Отдельных глобальных классов компонентов и CSS Modules нет.

- Оформление задаётся utility-классами непосредственно в JSX. Общие цвета (`text-ink`, `bg-paper`, `bg-violet`), шрифты (`font-sans`, `font-serif`) берутся из темы. Новые повторяющиеся значения добавляйте в `@theme`; произвольные значения оставляйте для уникальной геометрии и декора.
- Верстка mobile-first. Существующие размеры сохранены: `xs` — 360 px, `md` — 700 px, `lg` — 900 px, `xl` — 1000 px, `2xl` — 1100 px. Это настройки проекта, а не стандартные размеры Tailwind. Для небольшого экрана до 360 px используется `max-xs:`.
- Повторяющиеся элементы оформляйте React-компонентами. `Container` задаёт ширину и поля страницы; `Button` и `ButtonLink` используют общие варианты `primary`, `outline`, `light`; `CourseGrid` управляет расположением карточек. Не копируйте их наборы классов в страницы.
- Условные классы объединяйте через `cn()` из `src/lib/cn.ts` (`clsx` + `tailwind-merge`). Для вариантов задавайте таблицы **полных литеральных классов**, как `courseArtStyles`. Не собирайте имена классов интерполяцией наподобие `bg-${color}`: такие классы Tailwind не обнаруживает.
- Состояния и адаптацию задавайте вариантами `hover:`, `focus-visible:`, `disabled:`, `group-open:`, `motion-reduce:` и префиксами размеров. Сохраняйте видимый фокус и области нажатия не менее 44 px.
- Prettier с `prettier-plugin-tailwindcss` сортирует классы автоматически. Команды из корня: `pnpm format` и `pnpm format:check`. Браузерные тесты используют роли, подписи и `data-testid`, чтобы изменение utility-классов не ломало проверки.

Требуются Node.js 22 и pnpm 11.

```bash
pnpm install
pnpm dev
```

Откройте `http://localhost:3000`. Проверки: `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`. Команда `pnpm test:e2e` проверяет страницы при ширине 320, 375, 768 и 1440 пикселей в установленном Google Chrome. Если production-сборка уже запущена, задайте `E2E_BASE_URL=http://127.0.0.1:3000`, чтобы тесты использовали её.

Каталог меняется в `packages/catalog/src/index.ts`. После изменения файлов приложение нужно собрать и развернуть снова. Главная, каталог и страницы курсов принудительно рендерятся на сервере. Форма отправляет `POST /api/leads`; сервер проверяет имя, телефон, email, выбранный курс и согласие, а затем отправляет письмо. Заявки не сохраняются в базе. Без SMTP-реквизитов форма показывает ошибку, поэтому для её проверки настройте `.env.local` в `apps/web` по образцу `.env.example`.

## Размещение на Linux-сервере

Требуются актуальные Docker Engine и плагин Docker Compose. Для получения сертификата домен должен указывать на публичный IP сервера, а входящие TCP-порты 80 и 443 должны быть доступны. Для HTTP/3 также откройте UDP 443.

1. Скопируйте репозиторий на сервер и выполните `cp .env.example .env`.
2. В `.env` задайте `SITE_ADDRESS=ваш-домен.ru`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` и `LEAD_TO`. Используйте адрес отправителя, разрешённый вашим SMTP-провайдером. Файл `.env` не добавляйте в Git.
3. Выполните `docker compose up -d --build`. Caddy направит запросы к Next.js и автоматически настроит HTTPS. Данные сертификатов сохраняются в Docker volume `caddy_data`.
4. Проверьте страницу и отправьте тестовую заявку. Обновление: получите свежий код и повторите `docker compose up -d --build`.

Для проверки контейнеров на локальной машине оставьте `SITE_ADDRESS=:80`; сайт будет доступен по HTTP на `http://localhost`. Убедитесь, что порт 80 свободен.

## Перед публичным запуском

- Замените демонстрационные программы, тексты и оформление.
- Заполните страницу `/privacy` реальными сведениями об обработке персональных данных и проверьте форму согласия.
- После готовности содержимого включите индексацию в `apps/web/src/app/layout.tsx`: сейчас поисковым системам задано `noindex`.
- Проверьте SMTP-отправку с адреса вашего домена и доставку писем в `LEAD_TO`.

Онлайн-оплата и административная панель пока не предусмотрены.
