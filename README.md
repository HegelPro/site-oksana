# Сайт онлайн-курсов Оксаны

Монорепозиторий на pnpm. Сайт на Next.js находится в `apps/web`, схема файлов курсов — в `packages/catalog`.

Дизайн использует предоставленные логотип и фотографии из `apps/web/public/images`. Шрифты Manrope и Cormorant Garamond с кириллицей поставляются локально через Fontsource: запросы к Google Fonts при открытии сайта и сборке не нужны.

## Как добавить курс

Создайте файл в `apps/web/content/courses`, например `morning-yoga.md`. Имя файла задаёт адрес `/courses/morning-yoga` и используется в заявках. Чтобы сохранить адрес и связь с заявками, оставляйте имя файла прежним при редактировании курса.

В начале файла укажите название в блоке YAML между строками `---`. После блока пишите описание в Markdown. Названия и описания достаточно для публикации курса.

```md
---
title: Утренняя йога
summary: Короткие утренние занятия в комфортном темпе.
draft: true
---

Занятия начинаются с **мягкой разминки** и завершаются расслаблением.
```

Схема содержит девять полей. Обязательное поле — `title`. Дополнительные поля — `summary` (текст карточки), `format`, `duration`, `schedule`, `price` (целое число в рублях), `cover` (локальный путь `src` в `/images/` и описание `alt`), `order` (порядок карточек) и `draft`. Готовый курс появится в каталоге и на главной при `draft: false` или без поля `draft`. Черновик доступен по прямому адресу при разработке. В production его страница и форма закрыты.

Чтобы добавить визуальный акцент, вставьте в описание цитату (`> Текст цитаты`) или картинку (`![Описание картинки](/images/файл.webp)`). Локальные файлы хранятся в `apps/web/public/images`, также поддерживаются прямые HTTPS-ссылки на изображения. Для подзаголовков используйте `##` и `###`. Длинные материалы можно свернуть в блок.

```md
:::details[Смотреть программу]

### Первый день

- Знакомство с практикой.

:::
```

Примеры в `apps/web/content/courses` — `yoga-ayurveda-inner-calm.md` с иллюстрацией внутри текста и `yoga-ayurveda-14-days.md` с раскрывающейся программой. У курсов одинаковые названия, а заявки различаются по адресу курса (`courseSlug`). На локальном сервере достаточно обновить страницу после сохранения файла. Для размещённого сайта пересоберите и разверните приложение.

## Локальная разработка

### Стили и компоненты

Весь интерфейс использует **Tailwind CSS 4** через `@tailwindcss/postcss`. Единственная глобальная таблица — `apps/web/src/app/globals.css`: импорт Tailwind, токены `@theme` и базовые правила типографики, фокуса и уменьшения движения. Отдельных глобальных классов компонентов и CSS Modules нет.

- Оформление задаётся utility-классами непосредственно в JSX. Общие цвета (`text-ink`, `bg-paper`, `bg-violet`), шрифты (`font-sans`, `font-serif`) берутся из темы. Новые повторяющиеся значения добавляйте в `@theme`; произвольные значения оставляйте для уникальной геометрии и декора.
- Верстка mobile-first. Существующие размеры сохранены: `xs` — 360 px, `md` — 700 px, `lg` — 900 px, `xl` — 1000 px, `2xl` — 1100 px. Это настройки проекта, а не стандартные размеры Tailwind. Для небольшого экрана до 360 px используется `max-xs:`.
- Повторяющиеся элементы оформляйте React-компонентами. `Container` задаёт ширину и поля страницы; `Button` и `ButtonLink` используют общие варианты `primary`, `outline`, `light`; `CourseGrid` управляет расположением карточек. Не копируйте их наборы классов в страницы.
- Условные классы объединяйте через `cn()` из `src/lib/cn.ts` (`clsx` + `tailwind-merge`). В вариантах используйте полные имена классов, чтобы Tailwind обнаружил их при сборке.
- Состояния и адаптацию задавайте вариантами `hover:`, `focus-visible:`, `disabled:`, `group-open:`, `motion-reduce:` и префиксами размеров. Сохраняйте видимый фокус и области нажатия не менее 44 px.
- Prettier с `prettier-plugin-tailwindcss` сортирует классы автоматически. Команды из корня: `pnpm format` и `pnpm format:check`. Браузерные тесты используют роли, подписи и `data-testid`, чтобы изменение utility-классов не ломало проверки.

Требуются Node.js 22, pnpm 11 и запущенный Docker с актуальным плагином Compose v2. Команды выполняются из корня проекта.

```powershell
Copy-Item apps/web/.env.development.example apps/web/.env.development.local
pnpm install
pnpm db:up
pnpm dev
```

При первом запуске скопируйте шаблон один раз. В Bash используйте `cp` вместо `Copy-Item`. `pnpm db:up` запускает PostgreSQL 17 и применяет миграции, `pnpm db:migrate` применяет новые SQL-файлы, а `pnpm db:down` останавливает локальную базу с сохранением её тома.

Если локальный PostgreSQL уже работает и миграции применены, достаточно `pnpm dev`. На Windows для кластера, подготовленного в `data/pg17-local`, используйте из корня проекта следующие команды после перезагрузки и для остановки. Перед переходом на Docker остановите этот экземпляр, чтобы освободить порт.

```powershell
$pgCtl = '.\data\pg17-local\package\native\bin\pg_ctl.exe'
& $pgCtl -D .\data\pg17-local\cluster -l .\data\pg17-local\postgres.log -w start
# Остановка
& $pgCtl -D .\data\pg17-local\cluster -m fast -w stop
```

Откройте `http://localhost:3000`, выберите курс и отправьте форму с тестовыми контактами. `http://localhost:3000/api/ready` возвращает `200`, когда сайт подключился к PostgreSQL и роль приложения видит нужную схему. Проверка `/api/health` показывает, что запущен сам Next.js.

Локальный Compose-проект называется `oksana-dev` и использует свой том. Для подключения из pgAdmin укажите `127.0.0.1`, порт `5433`, базу `oksana_dev`, пользователя `postgres` и `POSTGRES_PASSWORD` из `apps/web/.env.development.local`. Next.js подключается в роли `oksana_app`. Если порт занят, измените `PGPORT` в том же файле. Настройки сервера хранятся в корневом `.env`, настройки разработки — в `apps/web/.env.development.local`.

```bash
docker compose --env-file apps/web/.env.development.local -f compose.dev.yaml exec postgres psql -U postgres -d oksana_dev
```

Команды проверки проекта — `pnpm typecheck`, `pnpm lint`, `pnpm test` и `pnpm build`. `pnpm test:e2e` проверяет страницы на нескольких размерах экрана в Google Chrome и подменяет ответ API при заполнении формы. Для проверки production-сборки задайте `E2E_BASE_URL` с адресом запущенного сайта.

## Заявки на курсы

Форма отправляет `POST /api/leads`. Сервер проверяет поля и записывает заявку через `pg` в `public.leads`. Запись и согласие фиксируются до попытки отправить письмо. Повтор того же идентификатора отправки подтверждает уже сохранённую заявку. Скрытое поле защиты от ботов в таблицу не попадает.

| Поля | Что хранится |
| --- | --- |
| `name`, `phone`, `email` | Контактные данные из формы |
| `message` | Необязательное сообщение до 2 000 символов. У пустых сообщений и старых заявок значение `NULL` |
| `course_slug` | Адресный идентификатор курса, на котором открыли форму |
| `id` | UUID заявки |
| `created_at`, `consent_at` | Время приёма заявки и согласия, оба поля имеют тип `timestamptz` |
| `consent_version` | Редакция политики, которую пользователь принял. У старых записей значение `NULL` |
| `status` | Этап обработки заявки — `new`, `contacted` или `closed` |
| `mail_status`, `mail_sent_at` | Состояние уведомления и время подтверждения отправки |

В dev письма отключены, поэтому у новых записей `mail_status = 'skipped'`. На сервере при включённом SMTP заявка сначала получает `pending`, при успешной отправке — `sent`, а при ошибке — `failed`. Даже при ошибке SMTP заявка остаётся в базе. Письма автоматически не повторяются. Проверяйте заявки со статусами `pending` и `failed` и связывайтесь с людьми по сохранённым контактам.

```sql
SELECT id, created_at, course_slug, name, phone, email, message, status, mail_status
FROM public.leads
ORDER BY created_at DESC
LIMIT 20;
```

Статус обработки меняйте в pgAdmin или SQL по конкретному `id`, например `UPDATE public.leads SET status = 'contacted' WHERE id = '<uuid>';`. Роль сайта может добавлять заявки и обновлять состояние уведомления. Обработку заявок ведите под учётной записью оператора или администратора. Доступ к данным и копиям ограничьте сотрудниками, которые обрабатывают заявки.

## Production и GitHub Actions

Ветка `main` проходит проверки и публикует образы сайта и миграций в GHCR. Переменная `DEPLOY_ENABLED` открывает автоматический деплой проверенного коммита по SSH. Caddy обслуживает HTTPS, PostgreSQL хранит заявки в отдельном постоянном томе.
